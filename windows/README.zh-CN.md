# RouteMeter Windows 预览版

Windows 11 主屏水平任务栏里的直连 / 代理网速组件，面向 Clash Verge Rev / Mihomo。点击任务栏数字或托盘图标打开累计统计和接入设置。不是桌面浮窗。

## 安装与接入

1. 解压整个发布包到固定目录，运行 `RouteMeter.exe`。已包含 .NET 8 运行时，无需安装 SDK 或申请管理员权限。首版未进行代码签名。
2. 在详细面板点击「接入 Clash Verge · 复制计量脚本」。建议勾选「后台转发器开机启动」。接入后的代理连接依赖后台转发器，必须先启动它。
3. 复制本机接入脚本，放入 Clash Verge 的「订阅 → 全局扩展脚本」，保存并重新加载配置。脚本包含本机随机凭据，不要公开分享。
4. 如果已经有扩展脚本，保留原来的 `main` 和原有逻辑，添加生成脚本中的 `routeMeter` 函数，然后在现有 `main` 的最后返回 `routeMeter(config)`。订阅级扩展可能晚于全局扩展执行，需保证最终增加/修改的节点也经过计量处理。
5. 继续选择原来的订阅节点并正常访问网络；`RouteMeter Local Meter` 仅用于本机转发，不要把它作为出口节点选择。面板会从「等待接入」变成「代理实测」。未接入节点会触发覆盖检查提示。

使用 Mihomo 官方 `dialer-proxy` 配置功能，不替换、不修改内核或 Clash Verge 程序文件。脚本处理内联节点和 proxy-providers 的 override，保留分流规则、节点参数、现有选择组和 DNS 配置。普通订阅更新后脚本会重新应用。

已有代理链、网卡绑定、路由标记时，脚本会拒绝自动覆盖，需人工把计量器接到原有链的最外层。需要特殊 DNS 才能解析的节点域名、特殊出站协议及后续客户端更新仍需验证；转发器收到域名地址时使用 Windows 系统 DNS。

## 统计口径

- **代理**：独立 SOCKS5 转发器在实际转发 TCP / UDP 时累计的传输字节；连接关闭后数据仍然保留。不会因为两次界面采样间连接结束而漏掉已经转发的数据。
- **代理包括**：进入计量路径的加密协议/握手开销、节点健康检查等传输。不含本地计量 SOCKS 握手/UDP 包头，不含 IP/TCP 包头和操作系统重传。不是机场账单或套餐扣费的保证值。
- **直连 ≈**：从 Mihomo 活跃连接读取的采样参考，短连接可能漏计。只包含 Mihomo 管理的连接，不是整机所有直连网卡流量。
- **合计 ≈**：代理实测与直连参考相加，两者处于不同协议层，合计只作参考。
- K / M / G 按 1024 进位；速率单位为字节/秒。详细面板提供下载、上传和合计列，没有第三种流量分类。

代理完整性以所有目标节点实际使用生成的计量路径为前提。面板通过本地 API 核验节点的 `dialer-proxy`，有绕过的节点时不显示为完整接入。API 核验失败时实际后台计数仍继续，但面板不假装接入正常。未知协议/配置不可仅凭这一检查宣称绝对覆盖。

后台每两秒保存一次累计数据，正常停止会完成最终保存；进程崩溃、强制终止或断电可能丢失尚未落盘的部分。后台停止时计量路径不可用，受影响的代理连接会失败，需要重连；不会自动悄悄绕过计量器。面板退出不停止后台转发器。

当前转发器最多同时处理 512 个 TCP/UDP 会话；超出时拒绝新会话，现有会话继续运行。转发器会增加一层本机收发，尚未完成高吞吐性能测试。

## 日常使用、停用与卸载

- 点击任务栏数字打开统计。右键可隐藏任务栏显示或退出面板；托盘保留恢复入口。任务栏子窗口随 Explorer 显隐，位置跟随通知区变化，重启 Explorer 后会尝试重新嵌入。
- 面板「开机启动」控制面板本身；接入向导里的「后台转发器开机启动」单独控制后台。未开启后者时，下次登录应先运行 RouteMeter，再启动/连接 Clash Verge。
- 重置累计会清零后台代理计数和面板的直连参考值，不影响分流规则。
- 停用顺序：先恢复原来的扩展脚本并重新加载 Clash Verge，关闭两个开机启动选项，退出面板，然后运行 `RouteMeter.exe --stop-relay`。
- 完成停用后可删除程序目录。本机数据可保留，或单独删除 `%LOCALAPPDATA%\RouteMeter`。

本机目录包含加密凭据 `relay.json`、代理累计 `relay-state.json`、直连参考 `direct-reference.json` 和界面 `settings.json`。密码使用 Windows DPAPI 绑定当前用户；后台统计接口是当前用户专用的命名管道。转发器仅监听 `127.0.0.1:18765`，要求随机账号密码，不记录浏览目标、请求内容、订阅或节点凭据，不提供遥测。

端口冲突时，先撤销接入并停用后台，再编辑 `relay.json` 中的端口（1024–65535），重新打开程序并复制新脚本。不要分享文件中的其他内容。

## 开发与验证

Windows 上需要 .NET 8 SDK、Node.js、PowerShell。没有第三方 NuGet 依赖。

```powershell
./scripts/build-windows.ps1
# 可选：用已安装的官方 Mihomo 原版做隔离 TCP/UDP 集成测试
./scripts/build-windows.ps1 -MihomoPath 'C:\path\to\mihomo.exe'
```

测试使用临时目录、空闲端口、本机回显服务器和合成节点，不读取或改动运行中的代理配置，不向正常统计注入数据。协议测试逐字节核验短连接、大文件、半关闭、UDP、域名地址、IPv6、认证失败、分片拒绝及重启续计；后台测试核验独立进程、私有 IPC、并发读取、保存和重置；脚本测试核验规则保留、幂等及冲突拒绝。

2026-11-02 在 Windows 11 build 26300 / x64 上验证任务栏子窗口，确认父窗口为 `Shell_TrayWnd`，显示范围完全位于任务栏内。使用安装的 **官方 Mihomo v1.19.33** 在隔离配置下验证 TCP、UDP、直连旁路及 API 覆盖核验。尚未对真实订阅实施接入；多屏、竖直任务栏、各种节点协议及所有系统版本未完成验证。当前实现面向主屏水平任务栏。
